00:00–00:30开场 · 封面页
画面：PPT 封面页

大家好。今天给大家演示的是 GrayHunt —— 黑灰产情报智能体。

它能同时监控 Telegram 和 Twitter 两个平台，针对抖音、TikTok 这类平台上的刷量作弊、账号交易、引流诈骗等黑灰产风险，做到自动采集、智能清洗、沉淀落库、情报研判、可视化展示全链路自动化。

而这一切，用户只需要 一句话 就能驱动。

00:30–01:15痛点与架构
画面：翻到 PPT 第2页（痛点）→ 第3页（架构）

先说为什么要做这个。

黑灰产的广告散落在海量的 TG 群和推特里，人工根本盯不过来；更麻烦的是，关键的引流信息——微信号、电报号、域名、价目表，往往藏在图片里，纯文本搜索根本搜不到，特别容易漏。

（翻到架构页）GrayHunt 的解法是一个自定义智能体，它编排了一整条流水线：采集 → 关键词加 LLM 双层清洗 → 落库 → SQL 加 LLM 研判 → 生成可视化大屏。

下面我直接实操给大家看。

01:15–01:45进入智能体 · 展示配置
画面：浏览器 → localhost:2026 → Agents 页 → 点 ⚙️ 查看配置

这是我创建的智能体 telegram-twitter-gray-hunter。点开配置可以看到——

它绑定了采集、治理、分析三个 skill，加图表能力；

它的 SOUL 人设 里内置了工作流和几条关键护栏：严禁编造数据、账号实体不脱敏、优先用安全方式防封号、用真实路径。

这些护栏保证它跑出来的是真实、可溯源的情报。

01:45–04:00核心实操 · 一条提示词跑全流程
画面：agent 对话框，粘贴提示词发送，录制执行过程

现在我给它一条指令，让它跑完整流程。

完成一次完整的黑灰产情报作业： ① Telegram crawl --joined-only --days 30 采集已加入群 ② Twitter crawl-twitter --days 7 --vision 采集（开启图片视觉提取） ③ analyst 分析：风险分布、Top高危群、高频引流渠道（不脱敏），出研判报告 ④ report-html --embed-images 生成可视化页面 全程真实数据严禁编造，实体不脱敏，用真实路径。

可以看到它开始采集了——Telegram 用的是 joined-only 模式，只读已加入的群，不主动加群，所以零封号风险。

注意这里——它在做多模态视觉提取。黑灰产把价目表、微信号印在图片里规避检测，它用 LLM 把图里的文字识别出来。比如这条，从图片里读出了完整的「支付宝号价目表，白号158、年号439」，这是纯文本完全拿不到的。

采集完它自动进入分析——SQL 聚合统计风险分布，找出高频引流渠道，微信、电报、域名，而且完整不脱敏，因为情报就是要能溯源。

最后它调用 report-html 生成了可视化大屏，给出文件路径。

04:00–05:30成果展示 · 情报大屏
画面：打开 grayhunt.html 情报大屏，逐个演示交互

这就是它生成的 GrayHunt 情报大屏，现在有 378 条情报、44 个来源群组。

（演示筛选）顶部有四个筛选维度——风险等级、风险类别、来源平台、来源群组，都是按情报数量降序排的。比如筛'刷量作弊'，125 条全列出来。

（点群链接）群链接可以直接点进去；如果是私密群，旁边有 🔒 标识，提示需要登录且是群成员才能进。

（展示图片）这里——卡片直接展示了图片缩略图，下面绿色这块就是刚才从图片里提取出来的信息，账号、域名、价目表都还原出来了。

正文里的网址也都自动变成了可点击的蓝链，方便溯源。

05:30–06:30技术亮点 · 省 LLM 花销
画面：切回 PPT，第7页（省钱机制）→ 第8页（CASE表格）

最后讲一个核心技术亮点——怎么大幅降低 LLM 的花销。

我们用了四个手段：

第一，最关键的，关键词预筛——先用本地关键词粗筛，只有命中的才送 LLM，海量噪音在本地零成本就拦掉了；

第二，批量分析，多条合并成一次调用；第三，视觉提取按需开启，加落库去重，不重复研判。

06:30–07:00省钱 CASE · 重点慢讲
画面：PPT 第8页 CASE 表格，放慢强调数据

这是真实数据：

Telegram 这个小Z集团的群，30天历史 2795 条消息，经过关键词预筛，最终只有 2 条 真正送进 LLM——直接省掉了 99.9% 的 LLM 调用。

Twitter 也是，748 条筛到 141 条，再叠加批量调用，请求次数又降 90% 以上。

如果用最朴素的方案把每条都喂给 LLM，要 2795 次调用；GrayHunt 实际只用了个位数次。整体 LLM 成本降到了原始方案的个位数百分比。
