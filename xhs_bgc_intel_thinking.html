01 · 项目起因

黑灰产不一定发生在“黑产平台”，公开内容平台也可能成为获客入口

很多黑灰产链路并不是一上来就完成交易，而是先在公开平台完成曝光、筛选、引流，再把潜在用户导向私域渠道进行转化。

曝光

用副业、教程、资源、经验分享等正常外壳包装异常业务，降低用户警惕。

筛选

通过评论区、关键词、私信暗示筛出有需求的用户，例如询价、求渠道、求带。

引流与转化

把用户引导至微信、QQ、Telegram、社群、网盘等站外渠道，完成后续交易或诈骗。

02 · 为什么选择 XHS

XHS 不是黑灰产平台，但非常适合观察黑灰产的前端获客

它同时具备搜索、推荐、评论互动和内容包装场景。正文负责制造可信外壳，评论区往往暴露真实需求。

平台特点

  • 流量大，内容曝光效率高。
  • 帖子适合包装成经验分享、避坑指南、兼职推荐。
  • 搜索场景强，用户会主动检索副业、渠道、资料、账号等关键词。
  • 评论区互动密集，容易出现询价、求资源、求联系方式等信号。

重点观察对象

正文包装 评论询价 私聊暗示 站外引流 黑话变体 作者昵称 账号属地 共享联系方式
03 · 主要方向

重点关注四类风险线索

引流型风险

正文讲一半，评论区引导“私聊、看主页、进群、加我”，最终将用户带到站外。

灰产服务型风险

以“代办、渠道、资源、技术、账号服务”等形式包装，可能涉及违规服务撮合。

诈骗前置型风险

用高收益、低门槛、内部渠道等话术吸引用户，后续可能导向诈骗或资金风险。

黑话变体型风险

通过谐音、缩写、错别字、表情、图片文字、模糊表达规避平台审核。

04 · 情报收集分析流程

Pipeline：采集 → 去重清洗 → 黑话种子提取 → 风险评估 → 可视化展示

1

数据采集

采集公开帖子、正文、评论、回复关系、互动数据和账号基础信息。

2

去重清洗

过滤重复模板、无意义评论和明显无关内容，保留高价值风险信号。

3

黑话种子提取

从已知黑话出发，发现共现词、变体词和新型隐晦表达。

4

风险评估

结合正文、评论、互动、引流和账号行为进行风险分层。

5

可视化展示

输出高风险帖子、命中原因、评论证据、账号关联和黑话趋势。

05 · 采集字段

从帖子、账号、评论三层收集情报

层级 字段 分析价值
帖子主体 标题、正文、发布时间、原帖链接、来源关键词、互动量 判断业务语境、内容包装方式和传播强度。
账号画像 作者昵称、用户 ID、属地、账号命名方式 昵称中常出现“车队、接待、起号、资源、通道”等线索。
评论区 评论内容、评论用户名、点赞数、询价和求联系方式表达 评论区能反映真实需求热度，也是站外引流的重要入口。
关联字段 联系方式、相似文案、共享用户 ID、重复黑话组合 用于团伙聚类，把单帖风险升级为组织化风险。
06 · 风险评估模型

把零散信号转成可排序的处置优先级

观察

普通讨论、泛泛提及、缺少交易信号，只作为词库扩展候选。

明细

risk_score > 50：进入情报明细，保留帖子、作者、黑话、评论证据。

团伙

max_risk > 60：进入团伙聚类展示，优先人工复核和处置。

风险信号 示例 为什么重要
高危业务类目 跑分、四件套、接码、解封、博彩诈骗 直接决定危害类型和处置优先级。
联系方式暴露 微信、QQ、Telegram、手机号、薇、扣扣、飞机 说明交易链路更明确，具备转化入口。
报价信息 200 元/单、0.2 元/粉、套餐价、包过 说明存在明确售卖意图。
评论询单 怎么联系、多少钱、想要、求带、怎么弄 衡量真实需求热度，辅助判断传播效果。
团伙关联 相同联系方式、相同作者、相似文案、共享用户 ID 从单帖线索升级为组织化线索。
07 · 黑话种子闭环

黑话不是一次性结果，而是下一轮采集入口

先用词典命中已知黑话，再用高风险样本发现新黑话，最后把新词回灌词库与采集关键词。

已知黑话

起号、养号、破播放、有效粉、S 单、接码、四件套、跑分、盘口、走水。

上下文来源

不仅看正文，还要看作者昵称、评论用户名和评论内容，这些位置常出现更直接的暗语。

回灌扩面

新词进入本地词典和下一轮搜索种子，让采集面持续扩大，同时减少重复 LLM 判断。

08 · Token 优化策略

不要让 LLM 分析全部原始数据，只让它处理高价值语义难题

01

规则先行

去重、字段清洗、联系方式、报价、关键词命中、互动统计、风险分计算都由代码完成。

02

先过滤再调用

无业务命中、低风险、无评论询单、无黑话、无联系方式的内容不进入 LLM。

03

只传压缩字段

只传作者昵称、标题、正文摘要、高价值评论、已命中标签和风险分，不传全量原文。

04

批量请求

一次处理 20-30 条结构化记录，要求模型输出 JSON 数组，减少请求开销和冗余提示词。

05

沉淀缓存

LLM 提取的新黑话写回词典；相同文本 hash、note_id、联系方式 hash 复用历史结果。

06

分层使用模型

规则处理确定性任务，轻量模型做短文本归类，主模型只做新黑话发现和复杂语义判断。

错误方式

把几千条帖子全文和全部评论直接丢给大模型，让模型从头分析。这样成本高、速度慢、输出也难复核。

推荐方式

先用规则和统计方法把原始数据压缩成高价值情报，再让 LLM 做黑话发现、隐晦表达识别和语义补充。

{ "note_id": "xxx", "author_nickname": "跑分车队", "title": "四件套通道", "content_excerpt": "盘口代收代付，接跑分...", "top_comments": ["怎么联系", "多少钱", "想上车"], "matched_keywords": ["跑分", "四件套", "代收代付"], "risk_score": 92 }
核心原则：用代码处理确定性任务，用 LLM 处理不确定语义；先过滤、再压缩、再批量调用，最后把结果沉淀成词典。
