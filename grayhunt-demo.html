03 / STEP 1 · 采集 + 清洗 + 落库

双平台智能采集

🔧 功能与逻辑

  • Telegram：crawl --joined-only 走 iter_dialogs 读已加入群，不 resolve 不加群 → 零封号风险
  • Twitter：crawl-twitter --vision 经 TikHub API，并对图片做多模态视觉提取
  • 采集即清洗即落库：关键词→LLM 过滤后写入 SQLite + JSON/CSV

🖼️ 多模态亮点

黑灰产把微信号、TG号、域名、价目表印在图片里规避文本检测。GrayHunt 用 LLM 视觉提取还原——例如识别出「支付宝白号¥158 / 年号¥439」整张价目表。

提示词示例 PROMPT
用 threat-intel-collector 采集情报： 1. Telegram：crawl --joined-only --days 30 （我已加入的所有群，最近30天，最安全） 2. Twitter：crawl-twitter --days 7 --vision （开启图片视觉提取：识别图中 微信/TG/QQ账号、域名、价目表、二维码） 完成后告诉我：各平台新增情报数、 风险等级分布、是否触发限流。

07 / COST · 核心亮点

如何大幅降低 LLM 花销

① 关键词预筛（省最多）

先用本地关键词（products × actions 矩阵）粗筛，只有命中的才送 LLM。海量噪音消息在本地零成本拦掉，LLM 只处理疑似目标。

② 批量分析

多条消息合并一次调用（batch_size=15），N 条只算 1 次请求，调用次数降一个量级。

③ 多模态按需 + 缓存去重

视觉提取（--vision）可关；落库 (day,id) 去重不重复研判；原始归档复用，规则变了不必重爬。

08 / COST · 实测 CASE

真实数据：关键词预筛省下 90%+ 调用

场景采集原始量关键词过滤后
(进 LLM)		LLM 实际处理占比省下
Telegram「小Z集团」群
30天历史		2,795 条2 条0.07%↓ 99.9%
Twitter 26词 × 10页748 条141 条18.9%↓ 81%
批量调用
(batch_size=15)		141 条 = 141 次≈ 10 次请求—↓ 93%
调用次数

若把 2,795 条全量喂给 LLM 逐条研判 ≈ 2,795 次调用；GrayHunt 经关键词预筛后仅 2 条进 LLM，直接省掉 99.9% 的 LLM 开销。 叠加批量调用，单次完整作业的 LLM 成本降到原始方案的 个位数百分比。
